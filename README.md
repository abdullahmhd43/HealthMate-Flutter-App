# HealthMate – Your Daily Health Companion

CI6330 Coursework 1. An offline personal health & wellness tracker built with
Flutter, Material 3, SQLite (`sqflite`) and Provider.

## 1. Requirements

- Flutter **3.27 or newer** (stable channel) with Dart 3.6+
- Android Studio / Xcode toolchains for the platform you run on

## 2. First-time setup (important)

This ZIP contains the full Dart source (`lib/`, `test/`, `pubspec.yaml`, ...).
The native platform folders (`android/`, `ios/`) are generated by Flutter itself,
so create them once inside the extracted folder:

```bash
cd HealthMate
flutter create --project-name healthmate --platforms=android,ios .
```

This only adds the missing platform files. It does not overwrite `lib/`,
`test/` or `pubspec.yaml`. (If you want other platforms, add e.g. `,windows,macos,linux`.)

## 2b. App icon

The launcher icon source files are in `assets/images/` (`app_icon.png`,
`app_icon_foreground.png`, `app_icon_background.png`). After the `flutter create`
step above and `flutter pub get`, generate the Android and iOS icons once:

```bash
dart run flutter_launcher_icons
```

## 3. Install dependencies

```bash
flutter pub get
```

## 4. Run the app

```bash
flutter run
```

## 5. Run analysis and tests

```bash
flutter analyze
flutter test
```

The database tests use `sqflite_common_ffi` with an in-memory database, so they
run on your computer without an emulator. On Linux this needs the SQLite
library (`sudo apt install libsqlite3-dev`).

## 6. Features

- Splash screen, then a 5-tab app (see `lib/features/dashboard/screens/main_shell.dart`), plus an **Add record** button.
- **Dashboard**: greeting, today's steps / calories / water with goal progress rings, 7-day steps chart, recent records, empty state when there is no data. Refreshes automatically after any add, edit or delete.
- **Add / Edit record**: date picker, numeric fields, required / whole-number / non-negative / maximum validation, duplicate-date protection.
- **History**: newest first, search by date (`2026-11`, `2026-11-06`, `06/11/2026`), single-date picker, date-range filter, edit, delete with confirmation, record details screen.
- **Analytics**: daily summary (browse any day), weekly chart for steps / water / calories with goal line, monthly totals (browse months), statistics (average steps, average water, total calories, best activity day).
- **Levels**: Low / Moderate / Good / Excellent chips show how each value compares with your goal.
- **Calories from steps**: calories are estimated while you type steps (uses your weight and height when the profile is set) and can still be edited.
- **Profile**: age, gender, height, weight; BMI with category; recommended step / water / calorie goals you can apply in one tap.
- **Weight tracker**: log weight by date, trend chart, change since start. The newest weight keeps your profile and BMI current.
- **Water quick-add**: +150 / +250 / +500 ml buttons on Home add to today's record.
- **Today's summary** (new): open it from the Home card. Shows steps walked, distance, calories burned and levels, plus a **water plan**: today's target (your goal plus extra for calories burned), how much you have drunk, how many ml / glasses are still left, whether you are ahead of or behind schedule for the time of day, and about how much to drink per hour. +150 / +250 / +500 ml buttons save straight to today's record.
- **More health data, reminders, streaks, achievements and automatic step counting** (stages 2-4): see `ANDROID_SETUP.md` for the Android permissions and Gradle edits they need.
- **Settings**: daily step / water / calorie goals, light / dark / system theme, sample-data controls, app info.
- 14 sample records (the 14 days *before* today, never today itself) are inserted **once**, only into an empty database, and are labelled "Sample". You can clear or re-add them in Settings. Your own records are never touched by "Clear samples": a sample you edit, or add steps/water to, becomes your own record. Samples do not count towards streaks or achievements.

## 7. Database

File: `healthmate.db` (created on first launch, reused afterwards, schema version 3).

```sql
CREATE TABLE health_records (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL UNIQUE,   -- ISO yyyy-MM-dd, one record per day
  steps INTEGER NOT NULL,
  calories INTEGER NOT NULL,
  water INTEGER NOT NULL       -- millilitres
);
```

Schema version 2 adds `weight_logs`, version 3 adds `sleep_logs`, `workout_logs` and `mood_logs`; `health_records` is unchanged and existing data is kept on upgrade:

```sql
CREATE TABLE weight_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL UNIQUE,
  weight_kg REAL NOT NULL
);
```

All queries are parameterised and live in
`lib/features/health_records/repositories/health_record_repository.dart`.
Schema upgrades go in `DatabaseHelper._onUpgrade` (`lib/core/database/database_helper.dart`).
Goals and theme are stored with `shared_preferences`.

## 8. Architecture

```
lib/
  main.dart, app.dart
  core/            constants, database helper, theme, utils (dates, validators), shared widgets
  features/
    dashboard/     DashboardStats (model), DashboardProvider, splash, shell, dashboard screen
    health_records/ model, repository, sample-data service, HealthRecordsProvider, form/history/detail screens
    analytics/     analytics screen, weekly bar chart (fl_chart)
    summary/       DailySummary (model), Today's summary screen, water glass, Home card
    settings/      UserGoals, SettingsProvider, settings screen
test/              database, validators, dashboard stats, providers, widgets, daily summary (logic + screen)
```

MVVM with Provider: widgets read `HealthRecordsProvider`, `DashboardProvider`
and `SettingsProvider`; providers call the repository; only the repository
touches SQLite.

## 9. Notes on automatic step counting

- Steps walked while the app was closed are counted when the next sensor reading
  arrives, as long as the previous reading was yesterday or today. After a gap of
  more than one day counting restarts from that reading.
- Phone reboots (any number per day) are handled by carrying today's count over.
- Writes to today's record (sensor steps, water buttons) are queued and always
  start from the row stored in SQLite, so they cannot overwrite each other.

## 10. iOS

Add to `ios/Runner/Info.plist` (inside `<dict>`):

```xml
<key>NSMotionUsageDescription</key>
<string>HealthMate counts your steps with the phone's motion sensor.</string>
```

Notifications and motion permissions are requested when you switch the feature on.
